Modelling NVIDIA Tensor Cores and AMD Matrix Cores Using MATLAB

By Faizan A. Khattak · 18 November 2026

Modern GPUs contain specialised hardware units designed to accelerate matrix multiplication. NVIDIA Tensor Cores and AMD Matrix Cores are examples of such units.

While these units provide substantial computational performance, understanding their numerical behaviour is equally important. Different floating-point formats, rounding modes and accumulation strategies can affect the accuracy of matrix computations.

In this article, I introduce a MATLAB toolbox that provides models of NVIDIA Tensor Cores and AMD Matrix Cores. We will look at how to set up the toolbox and perform matrix multiplication using different floating-point precisions.

1. What is the MATLAB Tensor Core toolbox?

The MATLAB Tensor Core repository provides accurate numerical models of tensor and matrix cores implemented in MATLAB.

The toolbox includes models for several NVIDIA GPU architectures, including Volta, Ampere, Hopper, Ada Lovelace and Blackwell. It also includes AMD Matrix Core models for CDNA generations 1, 2 and 3.

The models simulate matrix multiplication using floating-point inputs and outputs, together with configurable accumulation behaviour.

2. Supported GPU architectures

The repository includes models for the following architectures:

  • NVIDIA Volta: V100
  • NVIDIA Ampere: A100, A2, A30 and A40
  • NVIDIA Hopper: H100 and GH200
  • NVIDIA Ada Lovelace: RTX-1000 and L40S
  • NVIDIA Blackwell: B200
  • NVIDIA RTX Blackwell: RTX PRO 6000
  • AMD CDNA 1: M100
  • AMD CDNA 2: MI210 and MI250
  • AMD CDNA 3: MI300, MI300A and MI300X

3. Installation and setup

The toolbox requires MATLAB (or GNU Octave) and the CPFloat custom-precision floating-point simulator.

Step 1: Download the MATLAB Tensor Core repository.

Clone the repository using Git: 

git clone https://github.com/north-numerical-computing/MATLAB-tensor-core.git

Alternatively, download the repository as a ZIP file from GitHub.

Step 2: Set up CPFloat.

Download and configure CPFloat using its installation instructions:

CPFloat GitHub repository

For MATLAB, compile its MEX interface using make mexmat where Make is available. Add CPFloat's bin/ directory to the MATLAB search path.

Step 3: Add the toolbox directories to MATLAB.

Navigate to the downloaded MATLAB Tensor Core repository and execute: 

addpath('models');
addpath('models/tools');

You are now ready to use the built-in GPU models.

4. Your first Tensor Core matrix multiplication

Let us start with a simple example using the NVIDIA Blackwell B200 Tensor Core model.

We will use FP16 inputs and FP32 outputs. 

% Define input and output formats
inopts.format = 'binary16';
outopts.format = 'binary32';

% Generate random matrices and round to FP16
A = cpfloat(rand(4,4), inopts);
B = cpfloat(rand(4,4), inopts);

% Perform matrix multiplication using B200
D = B200TC(1, A, B, 1, 0, ...
           inopts.format, outopts.format);

The function computes a matrix multiplication using the B200 Tensor Core model.

The arguments specify the scaling factors, input matrices and floating-point formats. In this example, alpha is 1 and beta is 0.

Note: The example uses the built-in B200 model. You do not need to own an NVIDIA B200 GPU to run this numerical model.

5. Experimenting with FP8 arithmetic

Modern accelerators also support low-precision formats such as FP8. We can use the same model with FP8 inputs. 

% Set FP8 input format
inopts.format = 'fp8-e4m3';

% Generate and round input matrices
A = cpfloat(rand(4,4), inopts);
B = cpfloat(rand(4,4), inopts);

% Perform multiplication
D = B200TC(1, A, B, 1, 0, ...
           inopts.format, outopts.format);

This example illustrates how the model can be used to investigate the numerical behaviour of matrix multiplication under different input precisions.

6. Understanding the numerical behaviour

One of the main advantages of these models is that they allow researchers to investigate numerical characteristics of specialised matrix hardware.

Some of the features investigated include:

  • Support for subnormal floating-point numbers.
  • Extra bits used for significand alignment.
  • Additional carry bits during accumulation.
  • Rounding modes and normalisation behaviour.
  • Effective FMA accumulation size.

These characteristics are important when studying numerical accuracy, reproducibility and the effects of reduced-precision arithmetic in scientific computing.

7. Running experiments and validation

The repository also provides experiments and model validation data. These are useful starting points for understanding how the models can be used in numerical studies.

Explore the following directories:

  • models/ — GPU architecture models.
  • models/tools/ — Supporting MATLAB functions.

8. Multi-Word Arithmetic: Using Low-Precision Tensor Cores for Higher Accuracy

One particularly interesting application of Tensor Cores is multi-word arithmetic. This technique uses several low-precision floating-point numbers to represent a single higher-precision number.

The motivation is straightforward: specialised matrix hardware can perform low-precision matrix multiplication efficiently, but scientific computing applications often require much higher numerical accuracy.

Multi-word arithmetic provides a way to bridge this gap. Instead of representing a number using only one floating-point word, we represent it as the sum of multiple floating-point components.

8.1 The basic idea

Consider a real number x. We approximate it using a sum of p floating-point numbers:

Multi-word representation:

x ≈ x1 + x2 + ... + xp

Here, each component is stored in a lower-precision floating-point format. The first component contains the leading significant bits, while subsequent components represent the remaining error.

For example:

  • 1-word: One floating-point component.
  • 2-word: Two components representing one number.
  • 3-word: Three components.
  • 4-word: Four components.

Increasing the number of words can improve the effective precision of the representation, although the actual accuracy also depends on the decomposition and accumulation algorithms.

8.2 Extending the idea to matrix multiplication

Let A and B be two matrices. Their product is:

C = AB

Suppose each matrix is represented using p low-precision components:

A ≈ A1 + A2 + ... + Ap
B ≈ B1 + B2 + ... + Bp

Expanding the matrix product gives:

C ≈ Σi=1p Σj=1p AiBj

Each term is a matrix multiplication that can potentially be evaluated using a low-precision Tensor Core model. The resulting partial products must then be accumulated carefully.

This creates a trade-off between computational cost and numerical accuracy. More words generally require more matrix multiplications and more accumulation operations.

8.3 Why use Tensor Cores?

NVIDIA Tensor Cores are specialised units designed to accelerate matrix multiplication. Their low-precision arithmetic capabilities make them interesting building blocks for multi-word algorithms.

Rather than relying on a single high-precision matrix multiplication, a multi-word algorithm combines several lower-precision products.

The MATLAB Tensor Core toolbox provides numerical models that allow researchers to investigate the behaviour of these matrix operations without requiring physical access to every GPU architecture being modelled.

8.4 Understanding the experiment

The multi-word arithmetic experiment in the repository's experiments/ directory can be used as a starting point for investigating how the number of floating-point components affects matrix multiplication accuracy.

The general experimental procedure is:

  1. Generate test matrices A and B.
  2. Compute a high-precision reference product.
  3. Decompose the matrices into multiple low-precision words.
  4. Evaluate the partial matrix products using the selected Tensor Core model.
  5. Accumulate the partial products.
  6. Compare the result against the reference product.
  7. Repeat for different word counts and floating-point formats.

8.5 Measuring numerical accuracy

A useful way to compare the computed matrix product with a reference result is the relative Frobenius norm error:

Relative error = ||Ccomputed - Creference||F / ||Creference||F

Here, Creference is computed using a higher-precision reference calculation, while Ccomputed is the result produced by the multi-word algorithm.

This metric provides an indication of how closely the multi-word result approximates the reference product.

8.6 What should we investigate?

Several questions make this experiment particularly interesting from a numerical linear algebra perspective:

  • How does accuracy change as the number of words increases?
  • How does the choice of FP8, FP16 or BF16 affect the result?
  • How does the accumulation strategy influence the final error?
  • Do different Tensor Core generations produce different numerical behaviour?
  • What is the computational cost of obtaining higher accuracy?

These questions help us understand whether low-precision hardware can be used to perform matrix multiplication with accuracy approaching higher-precision arithmetic.

8.7 Reproducing the experiment

To reproduce the experiment, first clone the MATLAB Tensor Core repository: 

git clone https://github.com/north-numerical-computing/MATLAB-tensor-core.git

cd MATLAB-tensor-core

Configure CPFloat and add the model directories to your MATLAB path: 

addpath('models');
addpath('models/tools');

Next, navigate to the experiments/ directory and identify the multi-word arithmetic experiment script. Follow the script's configuration and execution instructions to reproduce the original results.

9. Conclusion

The MATLAB Tensor Core toolbox provides a useful environment for studying the numerical behaviour of modern GPU matrix multiplication hardware.

By experimenting with different input and output formats, researchers can investigate the effects of floating-point precision, accumulation and rounding on matrix computations.

The toolbox is particularly useful for research in numerical linear algebra, high-performance computing and mixed-precision algorithms.
